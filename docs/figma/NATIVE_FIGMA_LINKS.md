## Built and checked

- 20 native editable 1280 × 800 screen frames.
- Library Button and Input Field instances, shared Inter text styles and scoped color/spacing variables.
- 126 navigation actions between screens; nine buttons refer to their current screen and have no navigation action.
- Three native flow starting points: Applicant journey, Organizer journey, Account journey.
- All transition targets existed during creation; no direct screen element exceeded its frame bounds.
- Browse was visually inspected in Figma. The Starter tool limit prevented further screenshot inspection of Review and validation screens. No browser click-through test has been completed.

## Before defense and submission

1. Open Share and allow the instructor to view the file. If the course accepts public link access, use Anyone with the link → Can view. Verify access in a signed-out browser.
2. Run Browse → Open group → Apply → Submit → Pending → Organizer view → Review → Accept → applicant Accepted → My groups.
3. Reset to Pending and run Review → Reject → applicant Rejected. Check registration, sign-in, application and group-time error examples.
4. Use this prototype link in the submission PDF after verifying access. The supplied PDF contains the actual link but remains DRAFT because ERD is not yet on main and view access is unverified.

This is a low-fidelity prototype with fixed sample states. Form values and filters are examples. It does not authenticate users, persist data or calculate scores at runtime.
